# 마주봄 2분 피치 · 발표 전략 결정사항 (2026-09-15 정리)

> 팀 공유용. 발표 형식을 "PPT + 시연영상"으로 정하기까지 논의한 내용과, 그 결과 확정된 것들을 정리했습니다.
> 관련 파일: `pitch.html`(슬라이드) · `발표대본_2분.md`(대본) · `촬영콘티.md`(촬영 계획)

---

## 1. 결론 먼저

**PPT + 시연영상은 맞는 선택입니다.** 단, 이번 자리는 발표가 아니라 **2분 피치**라서 기존 5분·9장 덱을 그대로 줄이는 게 아니라 **6장·2분으로 다시 짰습니다.** 영상은 40초, 슬라이드는 6장, 발표자는 1명입니다.

## 2. 전제 조건 (확인된 사실)

| 항목 | 내용 |
|---|---|
| 자리 | 외부 기관·심사 대상 피칭. 기본 2분, 영상 포함 시 2분 30초까지 허용 |
| 청중 | 혼합. 기술 세부보다 **아이디어 · 기존 기술과의 차이 · 독창성**을 쉽게 보길 원함 |
| 발표 환경 | 우리 노트북을 모니터에 연결. 27인치 내외, 심사위원 1~2m 거리 |
| 기존 방식의 한계 | 부스에서 심사위원이 30초 보고 지나가서 "감지가 아니라 예측"이라는 핵심을 설명할 시간이 없었음 |
| 실물 | mmWave + ToF + 라즈베리파이 실제 하드웨어 동작. 대시보드(평면도 + 실위치 점 + 위험 뱃지)와 폰 푸시 알림 동작 |
| 데이터 상태 | 팀원 대상 **실측**으로 검증된 것: 불안정 보행 z-score 구분, 이탈 전조 감지. **30일 개인 기준선은 합성(시뮬레이션) 데이터** 기반 |
| 일정 | 9/16 촬영(학생 배우 2명), 9/17 발표 |

## 3. 확정된 구성

### 슬라이드 6장 (`pitch.html`)

| # | 내용 | 시간 |
|---|---|---|
| 1 | 훅: "넘어져서가 아니라 누워 지내다 돌아가신다 → 감지가 아니라 예측" + 숫자 하나(10명 중 4명) | 0:00–0:15 |
| 2 | 기존 방식의 현장 제약: 착용 밴드는 계속 차고 관리해야 하고, 비접촉 단일센서는 한 장면에 집중. 마주봄은 mmWave+ToF로 낮 보행과 밤 침상 자세를 함께 보는 차이. 실제 상용 제품 사례는 근거로만 표기 | 0:15–0:27 |
| 3 | 마주봄은 그날 낮에 이미 안다: 낮→저녁→밤→알림 하루 흐름 + "60초 전 vs 수 시간 전" 대비 + 비접촉·카메라 없음·착용 없음 | 0:27–0:40 |
| 4 | 어떻게: 센서 2개 역할 + "그 어르신의 평소"와 비교. 기존 덱 개념도 그대로 재활용 | 0:40–1:00 |
| 5 | 시연영상 40초, 클릭 재생, 무음 | 1:00–1:45 |
| 6 | 마무리: "넘어진 뒤 달려가는 게 아니라, 침대에서 나오기 전에 곁에 있겠습니다" | 1:45–2:05 |

뺀 것: 팀 소개, 목차, 시장 규모 표, 논문 근거, 기술 스택, 활용 효과. 2분에는 넣을 자리가 없습니다.

### 시연영상 40초 (`촬영콘티.md`)

이야기 하나: **낮 걸음 불안정 → 저녁에 위험 미리 판단 → 밤 걸터앉기·일어서려 함 → 폰 알림 → 간호사가 나오기 전에 도착 → 센서 클로즈업.**

- 왼쪽 실제 장면 + 오른쪽 대시보드 화면 녹화, 좌우 분할
- 낮/밤은 조명이 아니라 ☀️/🌙 아이콘 자막으로 구분 (한 번에 촬영 가능)
- 실제 낙상 장면은 넣지 않음 ("사후 감지"처럼 보여 메시지를 깎음)
- 실제 시스템 동시 녹화가 원칙. USB 불안정으로 30분 넘게 안 붙으면 화면 녹화를 나중에 맞춰 합성
- 기존 `scenario.mp4`(7/6)는 어둡고 대시보드가 안 읽히며 낮 보행·폰 알림이 없어 재촬영. 실패 시 대체용으로만 유지

## 4. 논의 과정에서 기각한 선택지와 이유

| 선택지 | 기각 이유 |
|---|---|
| 상황 2개(야간 이탈 + 주간 보행)를 독립적으로 보여주기 | 35~40초에 둘 다 넣으면 둘 다 안 보임. 하나의 이야기로 묶는 게 낫고, 실제로 "낮 걸음 → 밤 위험"이 이 프로젝트 독창성 그 자체 |
| 영상에 나레이션 넣기 | 현장 스피커 문제로 망하는 경우가 흔함. 발표자가 말로 덮는 게 안전 |
| 라이브 시연 | 밤 시나리오 재현에 시간이 걸리고, USB 불안정이 문서에 반복 블로커로 적혀 있음. 심사위원이 따로 요청할 때 보너스로만 |
| 경쟁 비교를 제품별 사양표로 길게 나열 | 2분 피치에서 숫자와 제품명만 읽으면 차이가 남지 않음. 실제 제품 3개는 접촉 여부·감지 범위를 보여주는 근거로만 쓰고, 제품별 정확도는 측정 조건이 달라 직접 비교하지 않음 |
| 폰 알림 화면을 슬라이드에 별도로 넣기 | 시간 없음. 영상 안 6초 컷으로 처리 |
| 성능 수치(정확도·F1) 제시 | 실환자 데이터가 아니고 초기 단계(이탈 예측 F1 42). 숫자를 내세우면 Q&A에서 무너짐 |

## 5. 정직성 원칙 (Q&A 대비)

- **성능처럼 말할 수 있는 것**: 팀원 대상 실측으로 불안정 보행 구분, 이탈 전조 감지, 다인 환경 환자 특정을 검증했다.
- **동작 원리로만 말할 것**: 30일 개인 기준선. "쌓일수록 정확해진다"를 성능 수치처럼 말하지 않는다.
- **"실제 환자에게 돌려봤나"에 대한 고정 답변**: "팀원 대상 실측으로 검증했고, 30일 기준선은 시뮬레이션 단계, 다음이 현장 실증입니다."
- 영상 자막에 "시연 장면" 표기는 넣지 않되, 물으면 "실제 시스템이 동작하는 걸 찍은 것"이라고 답한다.
